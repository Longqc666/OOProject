## 三、答辩准备（老师会挑一个设计决策问“为什么”）

| 可能被问 | 一句话答案（报告位置） |
|---|---|
| 为什么不用微服务？ | 续借要本地强一致、团队 3～5 人无专职运维；微服务的扩展性当前用不上，却要付分布式事务与排障成本（5.1、14.3） |
| 为什么把“续借申请”单独建实体？ | 传统系统只改 dueDate，无法表达幂等、对账与审计；申请是“这次续借发生过什么”的业务事实（6.1、7.2） |
| “待对账”是不是过度设计？ | ILS 超时是“结果未知”不是“失败”；直接判失败会让读者重试并重复顺延，破坏预约公平（7.2、8.2） |
| 为什么校验顺序是证状态→逾期→次数→预约？ | 先给最可行动的原因；顺序是业务规则，写在 ValidatorChain 构造处并有测试固定（6.2） |
| 为什么状态图里“续借校验中”不落库？ | 它只是判定过程的显式化，不改变持久状态；落库会让状态表膨胀且无业务价值（7.1） |
| 为什么 AI 方案 A 扩展性高却不选？ | 需求匹配度权重 0.40；它用最终一致更新借阅读模型，与 C3 冲突，且没有幂等/对账（14.3） |
| AI 自检表为什么不可信？ | 它把“最终一致”判为满足 C3，把没有预约类判为覆盖 BR-03；自检只复述提示词，没有指向元素（14.4 D13） |
| 你的设计和实验一怎么对应？ | 表 12 给出分析类→设计类映射；智能体会话移出核心，只留 ITool 端口（6.4） |
